# План: параметрические архетипы сцен (keyless «дорогая» картинка)

Дата: 2026-07-25 · Ветка: `feat/scene-archetypes` · Базис: `main` (ba3a2df)

## Проблема

`src/media/scene-markup.js` строит для каждой сцены один и тот же кадр:
заголовок + лид слева, круговая схема `topicDiagram` справа. Шесть сцен подряд с
одинаковой композицией читаются как слайд-шоу. Живой видеофон (`gpt-directed-*`)
это маскирует, но требует ключа Pexels — а на машине владельца нет ни ключей, ни
GPU, ни локальных весов. Значит «дорого» достигается композицией, типографикой и
движением.

Эталон — `hermest-board-svetlana-final-1080p (1).mp4`: чистая HTML/CSS-анимация,
снятая headless-браузером, где под каждый тезис нарисован свой осмысленный мокап.

## Заимствованное, а не переизобретённое

- Навык **client-ai-guide** (asset, borrow): паттерн «данные → самодостаточный
  HTML без CDN → проверка headless Chrome (`--dump-dom` / `--screenshot`)».
  Отсюда берём: инлайн всего, ноль внешних ссылок, приёмка скриншотом.
- Существующий композер: `scene-markup.js` (шелл + `#t=` freeze), `scene-frames.js`
  + `chrome-cdp.js` (один долгоживущий Chrome, пул вкладок, кадр = свежий
  документ на виртуальном времени), `platform-recipes.js` (размеры, safe zones).
- Факт из `providers-matrix.md`: бесплатных keyless-провайдеров картинки/видео
  нужного качества нет; локальная диффузия на этой машине невозможна. Путь
  «без ключей» = композиция.

## Архитектура

Разделяем «шелл сцены» и «архетип».

| Файл | Ответственность |
|---|---|
| `src/media/scene-design.js` | токены темы, escape/clamp, seeded RNG, `resolveSceneLayout` (safe zones), общий ambient-CSS |
| `src/media/scene-content.js` | `deriveSceneContent` (items/numbers/pair/quote/steps из карточки), `pickSceneArchetype`, `planSceneArchetypes` |
| `src/media/scene-archetypes.js` | рендер каждого архетипа → `{ stage, css, stageFlex }` |
| `src/media/scene-markup.js` | шелл: фон, бренд-бар, прогресс, caption-zone, freeze-скрипт; композиция с архетипом |

Шелл остаётся единственным владельцем `#t=`-заморозки, поэтому детерминизм по
виртуальному времени сохраняется для всех архетипов.

### Архетипы

`statement` (роли opening/closing), `device-mockup`, `board-columns`,
`format-trio`, `checklist`, `comparison`, `stat-highlight`, `flow-steps`,
`quote`, `metric-grid`, `classic` (текущий макет — fallback).

### Выбор

1. `card.sceneType` → архетип явно.
2. Иначе роль по позиции: индекс 0 → `statement:opening`, последняя (при ≥3
   сценах) → `statement:closing`.
3. Иначе эвристика по содержимому: колонки/канбан → `board-columns`; форматы
   кадра → `format-trio`; интерфейс/устройство → `device-mockup`; кавычки →
   `quote`; противопоставление → `comparison`; ≥2 числа → `metric-grid`; одно
   число → `stat-highlight`; шаги → `flow-steps`; перечисление ≥3 → `checklist`;
   иначе → `classic`.
4. `planSceneArchetypes` проходит по всей раскадровке и разводит подряд идущие
   одинаковые архетипы (ритм важнее «идеального» совпадения).

### Safe zones

`resolveSceneLayout` берёт insets как `max(текущий процент, recipe.safeZones.*)`.
Без рецепта геометрия ровно текущая; для 9:16 это чинит фактическое нарушение
(сейчас боковой отступ 54px против требуемых 96).

### Движение на всю длину сцены

Сейчас снимается фиксированные 2.8 с, дальше кадр клонируется (`tpad`) — внутреннее
движение умирает. Меняем окно захвата на **всю длительность сцены** (кап 900
кадров = 30 с при 30fps), плюс во всех архетипах есть бесконечные ambient-слои
(параллакс фона, дыхание панелей, бегущая подсветка шагов, блик по экрану
устройства). Фильтр-граф ffmpeg не меняется: `tpad` с нулевым добавком —
no-op, `trim` держит длительность.

Цена кадра растёт линейно; она измеряется фактически и фиксируется в отчёте.
`HERMEST_SCENE_BUILD_FRAME_LIMIT` остаётся аварийным ограничителем.

## Ограничения (жёсткие)

- Ноль новых npm-зависимостей, ноль внешних шрифтов/картинок/CDN.
- Ни одного `url(` и ни одного `https?://` (кроме svg xmlns) в разметке —
  существующий тест это стережёт. Следствие: SVG-градиенты через `fill="url(#…)"`
  запрещены, только CSS-градиенты и сплошные заливки.
- Весь текст карточки экранируется; тест на XSS расширяется на все архетипы.
- Только `DejaVu Sans` (стоит в системе).

## Этапы

1. `scene-design.js` — токены, layout, ambient. Тесты на safe zones.
2. `scene-content.js` — извлечение + выбор архетипа. Тесты на эвристику и dedupe.
3. `scene-archetypes.js` — 10 архетипов + вертикальные раскладки. Тесты на
   детерминизм, экранирование, вертикаль.
4. `scene-markup.js` — композиция; классический путь сохраняет текущий вид.
5. Проброс `sceneType`/`sceneData`: `content-pipeline.js`, `api/_lib/projects.js`.
6. Захват на всю сцену в `scene-frames.js`.
7. Рендер PNG-эталонов всех архетипов (16:9 и 9:16) через реальный Chrome.
8. Гейты: `test:unit`, `validate`, `build`.

## Что закрыто по стадиям 7–8 (ветка `feat/archetype-polish`)

Тесты движка (стадии 1–3 требовали их, но их не было ни одного):
`test/unit/scene-archetypes.test.mjs` — детерминизм, экранирование, офлайн,
вертикаль, эвристика, разведение, мусор на входе; по всем 12 макетам и обоим
форматам. `test/unit/subtitle-band.test.mjs` — геометрия полосы субтитров.

Тесты вскрыли пять дефектов движка: мёртвый разбор «было/стало» для кириллицы
(`\b` в JS не знает не-ASCII), `[object Object]` из мусорного `sceneData`,
`statement` из ротации вплотную к закрывающей сцене, подставка ноутбука за
safe zone в 9:16, потерянная подпись под цитатой.

### Полоса субтитров: измерено, а не оценено

`captionHeight = height * 0.16` был догадкой. Замер реального выжигания
(ffmpeg 8.0.1 + libass, продакшен-фильтр) показал, что `force_style` получал
MarginV в пикселях, тогда как libass читает ASS-единицы холста 384×288:

| кадр | было | стало |
|---|---|---|
| 1920×1080 | строка в 204px от низа, **наезд на сцену 113px** | строка в 57px, зазор до сцены 40px |
| 1080×1920 | **субтитра в кадре нет вообще** | строка в 300px, зазор до сцены 36px |

`src/media/subtitle-band.js` — единственный источник этих чисел и для
`ffmpeg-args.js`, и для `resolveSceneLayout`.

Вывод по «пустым нижним 40%»: полоса снизу не избыточна — она была
недостаточна. Пустота шла от того, что архетипы не заполняли сцену по высоте;
это и починено (`board-columns`, `comparison`, `metric-grid`, `flow-steps`,
`checklist`, `classic`).

## Риски

- Эвристика может «угадать» архетип не туда → всегда есть `card.sceneType`.
- Рост цены рендера из-за полного окна захвата → измерить, оставить кап и env-лимит.
- CSS-счётчик (`@property` + `counter()`) для набегающей цифры — Chrome-only;
  для нецелых значений откат на статический текст.
